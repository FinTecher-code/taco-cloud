# Java OOP 学习笔记

## 1. Lambda 表达式中的 `->` 是什么？

`->` 是 Java Lambda 表达式的语法符号，用于简化匿名内部类的写法。

```java
// Lambda 写法（简洁）
assertDoesNotThrow(() -> user.sayHello());

// 等价的匿名内部类写法（冗长）
assertDoesNotThrow(new Executable() {
    @Override
    public void execute() {
        user.sayHello();
    }
});
```

**语法结构：** `(参数) -> { 方法体 }`

```java
() -> user.sayHello()        // 无参数
(x, y) -> x + y              // 有参数，单条语句
x -> x * 2                   // 单个参数，可省略括号
(x, y) -> {                  // 多条语句，需要花括号
    int sum = x + y;
    return sum;
}
```

## 2. 为什么可以在 User 类中加入 main 方法？

`main` 方法本质上就是一个 `public static void` 的普通方法，**任何类都可以有 main 方法**。

- JVM 启动时会查找指定类中的 `main` 方法作为入口
- 学习阶段可以用来快速测试
- 生产环境建议用单元测试代替

---

## 3. `public class` 和 `class` 有什么区别？

| 特性 | `public class` | `class` (默认) |
|------|---------------|----------------|
| 访问范围 | 所有地方 | 同一个包内 |
| 其他包可访问 | ✅ 可以 | ❌ 不可以 |
| 使用场景 | 主要的、需要公开的类 | 辅助类、内部工具类 |
| 文件命名 | 文件名必须与类名相同 | 无要求 |

**规则：** 一个 `.java` 文件最多只能有一个 `public class`，文件名必须与它相同。

---

## 4. 为什么用 `protected` 不用 `public`？

核心原因：**封装性**。

| 访问修饰符 | 同类 | 同包 | 子类（不同包） | 其他类 |
|-----------|------|------|---------------|--------|
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

- `public`：谁都能访问，太开放，不安全
- `protected`：只有子类能访问，既方便继承，又保持封装
- `private`：只有自己能用，最严格的封装

---

## 5. 为什么 `private` 不用 `public`？

字段用 `private` 是封装的基本原则：**保护数据，控制访问**。

```java
class Manager extends Employee {
    private double bonus;  // 只有 Manager 内部能访问
}
```

**最佳实践：字段用 `private`，方法用 `public`。**

---

## 6. 为什么接口方法默认是 `abstract`？

接口的本质是**契约**，只规定"要做什么"，不规定"怎么做"。

- 接口方法如果有具体实现，就失去了接口的意义
- 既然一定是抽象的，`abstract` 关键字就省略不写了
- 具体实现交给各个类去完成

---

## 7. 抽象类除了定义接口，还有什么其他作用？

抽象类比接口强大得多：

1. **提供部分实现** — 可以有具体方法，子类共享
2. **持有状态** — 可以有成员变量和构造函数
3. **定义模板方法** — 父类定义流程，子类填充细节

| 特性 | 接口 | 抽象类 | 普通类 |
|------|------|--------|--------|
| 抽象方法 | ✅ | ✅ | ❌ |
| 具体方法 | ✅(default) | ✅ | ✅ |
| 成员变量 | ❌(只能常量) | ✅ | ✅ |
| 构造函数 | ❌ | ✅ | ✅ |
| 多继承 | ✅ | ❌(单继承) | ❌ |

---

## 8. 抽象类和普通类为什么只能单继承？

**核心原因：避免菱形继承问题（二义性）。**

```
      Animal
      /    \
    Dog    Cat
      \    /
      DogCat    ← eat() 到底继承谁的？
```

Java 禁止类多继承是为了简单安全，用**接口多实现**来弥补灵活性。

---

## 9. 多继承和多态的区别？

| 概念 | 含义 | Java 支持 |
|------|------|----------|
| 多继承 | 一个类继承多个父类 | ❌ 类不支持，✅ 接口可以多实现 |
| 多态 | 一个引用指向不同子类对象 | ✅ 完全支持 |
| 单继承 | 一个类只能有一个父类 | ✅ 抽象类、普通类都一样 |

---

## 10. `List.of()` 和 `new ArrayList<>()` 的区别？

| | `List.of()` | `new ArrayList<>()` |
|--|------------|---------------------|
| 可变性 | ❌ 不可变 | ✅ 可变 |
| 能 add/remove | ❌ 不能 | ✅ 可以 |
| Java 版本 | 9+ | 所有版本 |
| 适用场景 | 数据固定不变 | 需要动态增删元素 |

---

## 11. `List` 和 `ArrayList` 有什么不同？

**`List` 是接口，`ArrayList` 是实现类。**

- `List` 是"标准"，不能直接 new
- `ArrayList` 是"产品"，可以直接 new

```java
// ✅ 推荐写法：声明用接口，创建用实现类
List<String> list = new ArrayList<>();

// 好处：面向接口编程，以后换实现（如 LinkedList）不用改声明
```

## 12. Maven 和测试有什么关系？

Maven 不仅仅是包管理工具，它是一个完整的**项目管理和构建自动化工具**。

Maven 构建生命周期：`validate → compile → test → package → verify → install → deploy`

- `mvn compile` — 编译源代码
- `mvn test` — 编译并运行测试代码
- `mvn package` — 打包项目
