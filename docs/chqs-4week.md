### Q1 — MySQL root 超级用户

**来源:** 每日一练 App

**题目:** MySQL 中预设拥有最高权限的超级用户是？

**选项:**
1. Administrator
2. DBA
3. admin
4. root ✅

**我的答案:** root ✅
**正确答案:** root

**解析:**
- root 是 MySQL 内置的最高权限超级用户，拥有所有权限
- Administrator 是 Windows 系统管理员，非 MySQL 概念
- DBA 是数据库管理员职位，不是用户
- admin 是常见用户名，但不是 MySQL 预设超级用户

### Q2 — MySQL BETWEEN 区间查询

**来源:** 每日一练 App

**题目:** 测试整数列 i 是否至少为 1 且不超过 10 的正确表达式是？

**选项:**
1. `i BETWEEN 1 AND 10` ✅
2. `i IN INTERVAL(1, 10)`
3. `i IN INTERVAL(0, 11)`
4. `i BETWEEN 0 AND 11`

**我的答案:** `i BETWEEN 1 AND 10` ✅
**正确答案:** `i BETWEEN 1 AND 10`

**解析:**
- `BETWEEN 1 AND 10` 等价于 `i >= 1 AND i <= 10`，包含边界值
- `IN INTERVAL` 不是 MySQL 合法语法
- `BETWEEN 0 AND 11` 范围过大，不符合要求

### Q4 — 给已有表添加主键约束

**来源:** 每日一练 App

**题目:** `ALTER TABLE tbl_name ADD PRIMARY KEY (column_list)` 的功能是？

**选项:**
1. 创建一个主键，不能为空不能重复
2. 创建一个主键，能为空不能重复
3. 创建一个主键，不能为空能重复
4. 创建一个索引主键，不能为空不可重复 ✅

**我的答案:** 选项4 ✅
**正确答案:** 选项4

- 选项4 准确描述了主键的全部特性：索引主键、不能为空、不可重复


### Q5 — MyISAM 全文索引查询优化

**来源:** 每日一练 App

**题目:** MyISAM 表 user（字段 id, name, email），name 和 email 均已建全文索引，最有效查询关键词的写法是？

**选项:**
1. `select id,name from user where name like '%关键词%' or email like '%关键词%';`
2. `select id,name from user where match(name,email) against('关键词' in Boolean mode);` ✅
3. `select id,name from user where match(name) against('关键词' in Boolean mode) or match(email) against('关键词' in Boolean mode);`
4. `select id,name from user where match(name) against('关键词' in Boolean mode) union select id,name from user where match(email) against('关键词' in Boolean mode);`

**我的答案:** 选项2 ✅
**正确答案:** 选项2

**解析:**
- `LIKE '%关键词%'` 无法走索引，大表性能差
- 选项2 使用**联合全文索引** `MATCH(name, email)`，一次检索两列，效率最高
- 选项3、4 虽然也用了全文索引，但需要拆成两次检索
- MyISAM 支持全文索引，`IN BOOLEAN MODE` 支持布尔运算符

### Q6 — TDSQL 跨地域迁移数据一致性验证

**来源:** 每日一练 App

**题目:** 跨地域迁移后，在不影响业务的前提下，如何快速验证数据的完整性和一致性？

**选项:**
1. 对源和目标的数据文件逐个计算 MD5 值进行比对
2. 随机抽取 1% 的数据进行样本比对
3. 利用 TDSQL 内置的全局一致性快照功能生成对比报告 ✅
4. 在业务低峰期分别进行 COUNT(*) 统计对比

**我的答案:** 选项3 ✅
**正确答案:** 选项3

**解析:**
- 跨地域迁移后验证数据一致性，关键是**不影响业务**且**全量验证**
- **MD5 逐个比对**（选项1）：需要遍历所有数据文件，计算量大且需锁表，影响业务
- **1% 随机抽样**（选项2）：抽样比对不全面，无法保证 100% 一致
- **TDSQL 全局一致性快照**（选项3 ✅）：TDSQL 内置特性，可在业务运行状态下创建全局一致性快照并生成对比报告，**全量、在线、无侵入**
- **COUNT(*) 统计**（选项4）：只能比行数，比不了数据内容本身

**关键记忆:**
> TDSQL 跨地域迁移后一致性验证的**最佳实践**：利用内置的全局一致性快照功能，全量比对且不影响在线业务

### Q7 — TDSQL GTID 主从切换数据一致性

**来源:** 每日一练 App

**题目:** 基于 GTID 的主从切换过程中，如何确保数据一致性？

**选项:**
1. 检查主库和从库的 binlog 文件大小是否一致 ❌
2. 等待所有从库应用完主库的 GTID 事务 ✅
3. 
4. 

**我的答案:** 选项1 ❌
**正确答案:** 选项2

**解析:**
- **GTID**（Global Transaction Identifier）是 MySQL 中每个事务的唯一标识，主从复制通过 GTID 确保事务的全局有序
- 主从切换时，**关键是确保所有从库都已经应用了主库已执行的所有 GTID 事务**，这样切换后数据才不会丢失
- **检查 binlog 文件大小**（选项1 ❌）：文件大小相同不代表内容一致，更不能保证 GTID 事务全部应用完
- **等待所有从库应用完 GTID 事务**（选项2 ✅）：通过 `SHOW SLAVE STATUS` 检查 `Seconds_Behind_Master` 为 0，且 `Retrieved_Gtid_Set` 与 `Executed_Gtid_Set` 一致，才能保证数据完整

**关键记忆:**
> GTID 主从切换三步骤：
> 1️⃣ 等从库**追完所有 GTID**（关键！）
> 2️⃣ 停主库写入
> 3️⃣ 将从库提升为新主库
> ❌ **文件大小**不能作为一致性判断依据

### Q8 — TDSQL 架构模块描述

**来源:** 每日一练 App

**题目:** 下列对 TDSQL 模块/节点描述正确的选项是？

**选项:**
1. 资源池主要提供 IaaS 服务，包括计算、存储、网络等
2. 存储节点层具备很强的扩展性，可以垂直扩展、水平扩展
3. 计算层主要处理分布式事务协调，不存储数据，CPU 密集型 ✅
4. 计算层支持列式存储 ❌

**我的答案:** 选项4 ❌
**正确答案:** 选项3 ✅

**解析:**
- **选项1 ❌**：资源池更多是 PaaS 层面的资源抽象和管理，不仅仅是 IaaS；TDSQL 是分布式数据库，基础设施层面确实涉及计算存储网络，但这不是描述 TDSQL 模块/节点的核心
- **选项2 ❌**：存储节点层（SET）通过**水平扩展**（sharding）来扩展容量和性能，但**垂直扩展**不是存储节点层的主要特征描述，且说法太笼统
- **选项3 ✅**：计算层（SQL Engine / Proxy）负责**SQL 解析、分布式事务协调、读写分离、结果聚合**等，**不存储实际数据**，是典型的 **CPU 密集型**节点 ✅
- **选项4 ❌（你选的）**：TDSQL 计算层**不支持列式存储**。TDSQL 是**行式存储**的分布式数据库，列式存储是另一类数据库（如 ClickHouse、Greenplum）的特性

**关键记忆:**
> TDSQL 三层架构：
> - **计算层**（SQL Engine）：不存数据，CPU 密集型，管分布式事务 ✅
> - **存储层**（SET）：存数据，水平扩展
> - **资源层**：底层基础设施
> ❌ 计算层 **不支持列式存储**（这是行式数据库）

### Q9 — TDSQL KILL 大事务与主从切换

**来源:** 每日一练 App

**题目:** 目前系统中有一个较大事务正在运行，并且阻塞了其他的会话，我们需要先将其 kill 掉来保证其他会话的正常运行，下列说法正确的是？

**选项:**
1. 事务需要回滚，数据量较大的情况下需要等待较长时间，可行主从切换，将从机切换为主，以快速恢复业务 ✅
2. 事务需要回滚，即使数据量较大的情况下，由于具有分片机制，也不需要等待过长时间
3. 可进入管理台进行主从切换，将从机切换为主，避免大事务回滚
4. 可进入管理台进行主从切换，将从机切换为主，加快大事务回滚速率 ❌

**我的答案:** 选项4 ❌
**正确答案:** 选项1 ✅

**解析:**
- KILL 大事务后，事务需要**回滚**（rollback），数据量大时回滚时间确实很长（选项 1 前半句 ✅）
- 为了**快速恢复业务**，可以进行**主从切换**，将从库提升为主库，业务立刻即可恢复（选项 1 后半句 ✅）
- 原主库会在后台继续完成大事务的回滚，不影响新主库上的业务
- **选项2 ❌**：分片机制不影响大事务回滚的速度——回滚需要逐条 Undo，数据量大就是慢
- **选项3 ❌**：主从切换**不能避免**大事务回滚——原主库仍然需要回滚，只是对业务透明了
- **选项4 ❌（你选的）**：主从切换**不能加快回滚速率**——回滚速度取决于数据量和 IO，切换主从改变不了原主库的回滚速度。切换是为了**恢复业务**，不是加速回滚

**关键记忆:**
> KILL 大事务后：
> - 回滚得等，数据越大越久
> - 主从切换是让业务**先恢复**，不是让回滚**变快**或**消失**
> - 原主库默默在后台回滚，别打扰它 😅

### Q10 — TDSQL 实例描述

**来源:** 每日一练 App

**题目:** 下列关于 TDSQL 的实例，描述不正确的是？

**选项:**
1. 实例指的是数据库服务的集合，是提供数据库服务的基本单位
2. 实例可以通过赤兔界面进行创建、隔离、恢复、删除等操作
3. 实例可分为分布式实例和非分布式实例
4. 创建实例是必须创建一主两从的规格 ❌

**我的答案:** 选项4 ✅
**正确答案:** 选项4 ✅

**解析:**
- **选项1 ✅**：实例确实是数据库服务的集合和基本单位，描述正确
- **选项2 ✅**：赤兔（TDSQL 管理平台）支持对实例进行创建、隔离、恢复、删除等全生命周期操作，描述正确
- **选项3 ✅**：TDSQL 实例确实分为**分布式实例**和**非分布式实例**（单节点），描述正确
- **选项4 ❌（题目问的不正确的选项）**：创建实例**不必须**要一主两从，可以根据资源情况灵活选择**一主一从、一主两从**等规格，所以该描述是错误的，正是本题要找的答案

**关键记忆:**
> TDSQL 实例规格灵活：**一主一从、一主两从**都支持，没有"必须一主两从"的说法
