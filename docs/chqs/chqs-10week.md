### Q1 — 线程安全的容器

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据安全 / Java 集合

**题目:** 下列哪个是线程安全的容器？

**选项:**
1. java.util.Vector
2. java.util.ArrayList
3. java.util.LinkedList
4. java.util.HashSet

**我的答案:** 选项4（HashSet）❌
**正确答案:** 选项1（Vector）✅

**解析:**
- **Vector** 的方法内部使用 `synchronized` 关键字，是**线程安全**的容器
- ArrayList、LinkedList、HashSet 均为**非线程安全**容器
- 记忆点：
  - 线程安全容器（面试常考）：`Vector`（古老，全方法加锁）、`HashTable`（对应 HashMap 的线程安全版）、`ConcurrentHashMap`（分段锁/乐观锁，性能好）、`CopyOnWriteArrayList`、`Collections.synchronizedXxx()` 包装
  - HashMap vs HashTable vs ConcurrentHashMap 的区别必须会答：HashMap 非线程安全；HashTable 全表加锁；ConcurrentHashMap 锁粒度更细（JDK1.8 CAS + synchronized 锁桶）

### Q2 — 基于 synchronized 保证线程安全的容器

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据安全 / Java 集合

**题目:** 下列哪个容器使用 synchronized 关键字保证线程安全？

**选项:**
1. CopyOnWriteArrayList
2. HashTable
3. ConcurrentHashMap
4. CopyOnWriteArraySet

**我的答案:** 选项3（ConcurrentHashMap）❌
**正确答案:** 选项2（HashTable）✅

**解析:**
- **HashTable** 基于 `synchronized`（方法级全表锁）保证线程安全——本题考点
- CopyOnWriteArrayList/CopyOnWriteArraySet：基于**写时复制**（COW），读不加锁、写时复制新数组
- ConcurrentHashMap：基于 **ReentrantLock + CAS + 分段思想**（JDK1.7 分段锁 Segment 继承 ReentrantLock；JDK1.8 改为 CAS + synchronized 锁桶）
- 记忆点：
  - 线程安全容器三兄弟的锁机制：**HashTable = synchronized 全表锁**｜**ConcurrentHashMap = 分段锁/CAS**｜**CopyOnWrite 系列 = 写时复制**
  - 区分“用 synchronized 的”和“不用 synchronized 的”：Vector/HashTable 是 synchronized；ConcurrentHashMap 早期靠分段锁（Segment 本身是 ReentrantLock），JDK1.8 用 CAS+synchronized，都不是简单的方法级锁

### Q3 — 对称密码算法的适用性（加密）

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据安全 / 密码学

**题目:** 为了保障数据传输和存储安全，需要对一些重要的数据进行加密。由于对称密码算法____，所以特别适合于对数据进行加解密。

**选项:**
1. 比非对称密码算法更安全
2. 比非对称密码算法效率高
3. 比非对称密码算法密钥长度更长
4. 能同时用于数据签名

**我的答案:** 选项1 ❌
**正确答案:** 选项2 ✅

**解析:**
- 对称密码算法（AES、DES）相对非对称（RSA、ECC）的核心优势：**加解密速度快、计算开销小、效率高** → 适合加密大量数据
- 非对称算法虽然安全性不弱（安全性不取决于对称/非对称，而取决于密钥长度和算法强度），但计算复杂度高，通常用于**加密会话密钥**或**数字签名**，不直接加密大量数据
- ✗ 选项1 错：对称并不“比非对称更安全”，安全性取决于算法本身和密钥长度
- ✗ 选项3 错：非对称密钥通常更长（RSA 2048+），对称密钥较短（AES-128/256）
- ✗ 选项4 错：对称加密**不能直接用于数字签名**（签名要用非对称私钥）
- 记忆点：**对称 = 快 → 加密数据本体；非对称 = 慢 → 加密会话密钥/签名**；实际方案常为混合加密（非对称协商密钥 + 对称加密数据）

### Q4 — Session 生命周期描述错误的选项

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据安全 / Session

**题目:** 关于 session 的生命周期，下面选项中描述错误的是？

**选项:**
1. Session 在用户第一次访问服务器的时候自动创建
2. 只有访问 JSP、Servlet 等程序时才会创建 Session，只访问 HTML、IMAGE 等静态资源并不会创建 Session
3. Session 生成后，只要用户继续访问，服务器就会更新 Session 的最后访问时间，并维护该 Session
4. 为了获得更高的存取速度，服务器一般把 Session 放在内存里，而且所有用户共有一个 Session

**我的答案:** 选项4 ✅
**正确答案:** 选项4 ✅

**解析:**
- 选项4 描述**错误**（题目选错误的）：Session 确实是**每个用户独享一份**（通过 JSESSIONID 区分），不是“所有用户共用一个”；放在内存里是对的（速度快的代价是重启丢失）
- 选项1 正确：首次访问服务器（请求带 cookie/session）时自动创建
- 选项2 正确：只有访问动态资源（JSP/Servlet）才创建 Session，静态资源（HTML/图片）不触发
- 选项3 正确：持续访问会更新最后访问时间（滑动过期），保持 Session 存活
- 记忆点：
  - **Session 是“一人一份”**，靠 Cookie 里的 JSESSIONID 标识（URL 重写是兜底方案）
  - Session 默认放内存 → 快但重启丢失；集群部署要解决 Session 共享（粘性会话 / Redis 集中存储）

### Q1 — getSession() 方法的描述（选错误的）

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据安全 / Session

**题目:** getSession 方法可以获取 session 对象，它可以包含参数也可以不包含参数，针对 getSession 操作，下面选项中描述错误的是？

**选项:**
1. getSession()：当 session 存在时返回该 session，否则新建一个 session 并返回该对象
2. getSession(true)：当 session 存在时返回该 session，否则新建一个 session 并返回该对象
3. getSession(false)：当 session 存在时返回该 session，否则不会新建 session，返回 null
4. getSession()：当 session 存在时返回该 session，否则不会新建 session，返回 null

**我的答案:** 选项4 ✅
**正确答案:** 选项4 ✅

**解析:**
- 选项4 描述**错误**（题目选错误的）：`getSession()` **等价于 `getSession(true)`**，session 不存在时会**新建**并返回，不是返回 null
- 选项1 正确：无参 `getSession()` 与 `getSession(true)` 行为一致——存在即返回，不存在即新建
- 选项2 正确：`getSession(true)` 不存在时新建
- 选项3 正确：`getSession(false)` 不存在时**不新建**，返回 null
- 记忆点：
  - **`getSession()` = `getSession(true)`**（默认创建）；**`getSession(false)` 不创建**，用于只读判断是否已有会话
  - 典型用法：登录校验时用 `getSession(false)` 判断用户是否已登录，避免为每个静态请求都创建无用的 Session

### Q2 — 二叉树先序遍历的顺序

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 树

**题目:** 在树的遍历中，先序遍历的顺序正确的选项是？
1、根结点
2、先序遍历左子树
3、先序遍历右子树

**选项:**
1. 3、2、1
2. 1、2、3
3. 1、3、2
4. 2、3、1

**我的答案:** 选项2（1、2、3）✅
**正确答案:** 选项2 ✅

**解析:**
- 先序遍历（Preorder）顺序：**根结点 → 先序遍历左子树 → 先序遍历右子树**（即 1、2、3）
- 对照记忆：
  - 先序（Preorder）：根 → 左 → 右
  - 中序（Inorder）：左 → 根 → 右
  - 后序（Postorder）：左 → 右 → 根
- 记忆点：名称即顺序——“先”指的是**根最先**访问；遍历左右子树时仍按同一种序遍历递归进行

### Q3 — 完全二叉树中叶结点的特征

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 树

**题目:** 在完全二叉树中，若一个结点是叶结点，则它没____。

**选项:**
1. 左子结点
2. 右子结点
3. 左子结点和右子结点
4. 左子结点，右子结点和兄弟结点

**我的答案:** 选项3 ✅
**正确答案:** 选项3 ✅

  - 叶结点定义只看**孩子**，不看兄弟
  - 完全二叉树的性质：若某结点只有 1 个孩子，则必然是**左孩子**；最后一个非叶结点可能在倒数第二层

### Q4 — 哈希表相对于 BST 的优势

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 哈希表

**题目:** 哈希表相对于 BST 的优势是什么？

**选项:**
1. 哈希表可以自动排序键值对
2. 哈希表可以快速执行范围查询
3. 哈希表在插入、搜索和删除操作上具有常数时间复杂度
4. 哈希表不需要进行冗余的空间分配

**我的答案:** 选项3 ✅
**正确答案:** 选项3 ✅

**解析:**
- 哈希表利用**哈希函数**将键映射到存储桶中的位置，通过直接访问桶内元素，**平均情况**下插入、搜索、删除均为 **O(1) 常数时间**；而 BST 这些操作平均 O(log n)
- 对照记忆：
  - ✗ 选项1 错：哈希表**无序**，不会自动排序键值对（如 Java HashMap 不保证顺序；TreeMap 才有序）
  - ✗ 选项2 错：**范围查询**（如查 [a, b] 区间内所有键）是 BST 的优势（中序遍历有序），哈希表做不到，需要全量扫描
  - ✗ 选项4 错：哈希表为减少冲突通常需要**预分配较大空间/扩容**，空间浪费反而比 BST 多
- 记忆点：**哈希表 = 平均 O(1) 查插删，但无序、不支持范围查询；BST = O(log n)、有序、支持范围查询**；选型看需求：要顺序/区间 → BST（TreeMap/TreeSet）；只要快速查插删 → 哈希表（HashMap）

### Q5 — 判断两棵二叉树是否等价的最简洁高效方法

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 树

**题目:** 数据结构中，对于两棵二叉树，如果它们具有相同的结构且每个节点具有相同的值，则这两棵树被称为是等价的。给定两棵二叉树，下列哪种方法可以有效地判断它们是否等价，且代码更简洁高效？

**选项:**
1. 使用深度优先搜索（DFS）遍历两棵树，并比较每个节点的值
2. 使用广度优先搜索（BFS）遍历两棵树，并比较每个节点的值
3. 将两棵树转换为有序数组，并比较这两个数组是否相等
4. 直接比较两棵树的根节点值，如果相等则它们就是等价的

**我的答案:** 选项2（BFS）❌
**正确答案:** 选项1（DFS）✅

**解析:**
- **DFS（递归/前序）** 是判断二叉树等价的经典写法：同时递归比较左右子树，代码简洁（三五行的递归函数），且能在发现第一个不匹配节点时**提前返回**
- 对照分析：
  - 选项2 BFS 也能做，但需要额外维护**队列/层序状态**，代码更复杂，且没有剪枝优势
  - 选项3 转有序数组：二叉树**非搜索树时中序不唯一代表结构**，无法保证结构等价；且额外 O(n) 空间，不简洁
  - 选项4 只看根节点显然错误（两棵树等价要求**所有**对应节点值相同且结构相同）
- 记忆点：**“判断两棵树是否相同/等价”≈ 递归 DFS 模板题**（LeetCode 100）——`isSameTree(p, q)`：都空→true；一空一非空→false；值不等→false；否则递归左右子树

### Q6 — 排序二叉树的遍历与有序序列

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 树

**题目:** 对于一棵排序二叉树：____遍历可以得到有序序列。

**选项:**
1. 前序
2. 中序
3. 后序
4. 前序、中序、后序都可以

**我的答案:** 选项1（前序）❌
**正确答案:** 选项2（中序）✅

**解析:**
- **二叉排序树（BST）定义**：任意节点，**左子树所有节点值 < 该节点 < 右子树所有节点值**
- 中序遍历顺序为**左 → 根 → 右**，恰好按值从小到大输出 → **中序序列必有序**
- 对照记忆：
  - 前序：根 → 左 → 右（第一个是根，不保证有序）
  - 后序：左 → 右 → 根（最后一个是根，不保证有序）
  - 所以选项4 错，只有**中序**有序
- 记忆点：**“BST 中序遍历 = 有序序列”（升序）**——面试高频结论；若需降序，中序右→根→左即可

### Q7 — 选择排序的时间复杂度推算

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 排序

**题目:** 用选择排序对 100 个数字排序花了 100ms，如果使用同样性能的电脑花费 900ms，能对______个数字进行排序。

**选项:**
1. 300
2. 900
3. 100
4. 800

**我的答案:** 选项1（300）✅
**正确答案:** 选项1（300）✅

**解析:**
- 选择排序时间复杂度为 **O(n²)**：耗时与数据规模平方成正比
- 推算：耗时 100ms → 数据量 100；耗时 900ms = 9 × 100ms → 数据量应为 √9 × 100 = **300**（时间变为 9 倍，规模变为 3 倍）
- 公式：`T ∝ n²` → `T2/T1 = (n2/n1)²` → `900/100 = (n2/100)²` → `n2 = 100 × 3 = 300`
- 记忆点：**O(n²) 排序（选择/冒泡/插入）时间×k ⇒ 规模×√k**；反过来，规模×k ⇒ 时间×k²

### Q8 — 树转二叉树：右孩子对应的兄弟关系

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 树

**题目:** 设 X 是树 T 中的一个非根结点，B 是 T 所对应的二叉树，在 B 中，X 是其双亲的右孩子，下列说法正确的是？

**选项:**
1. 在树 T 中，X 是其双亲的第一个孩子
2. 在树 T 中，X 一定无右兄弟
3. 在树 T 中，X 一定是叶结点
4. 在树 T 中，X 一定有左兄弟

**我的答案:** 选项3（叶结点）❌
**正确答案:** 选项4（一定有左兄弟）✅

**解析:**
- **树转二叉树规则（孩子-兄弟表示法）**：
  - 结点的**第一个孩子** → 二叉树的**左孩子**
  - 结点的**下一个兄弟**（右兄弟） → 二叉树的**右孩子**
- 所以二叉树中 X 是双亲的**右孩子** ⇒ 在树 T 中 X 是某个兄弟的**后续兄弟** ⇒ 前面必有兄弟 ⇒ **一定有左兄弟**（选项4）
- 对照排除：
  - ✗ 选项1 错：右孩子对应的是“后面的兄弟”，不是第一个孩子（第一个孩子对应左孩子）
  - ✗ 选项2 错：X 在树中可能有右兄弟（右兄弟会继续变成 X 的右孩子）
  - ✗ 选项3 错：树中的 X 可以有孩子（它的孩子会变成它的左孩子）
- 记忆点：**树 → 二叉树：“左孩子右兄弟”**。口诀：*第一个孩子走左边，其余兄弟走右边*；反之，二叉树左子树 = 树的孩子链，右子树 = 树的兄弟链

### Q9 — 按先进后出原则组织数据的结构

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 栈

**题目:** 下列数据结构中，按先进后出原则组织数据的是？

**选项:**
1. 线性链表
2. 栈
3. 循环链表
4. 顺序表

**我的答案:** 选项2（栈）✅
**正确答案:** 选项2（栈）✅

**解析:**
- **栈（Stack）** 按**先进后出（FILO/LIFO）**原则组织数据：只在一端（栈顶）插入和删除
- 对照记忆：
  - **队列（Queue）**：先进先出（FIFO）
  - 线性链表/循环链表/顺序表都是按**存储方式**分类，不限定进出顺序
- 记忆点：**栈 = 弹夹/叠盘子（后进先出）；队列 = 排队（先进先出）**；栈顶插入删除，队列队尾入队头出

### Q10 — 非线性数据结构

**来源:** 每日一练 App（岛屿主页在线答题）
**分类:** 数据结构 / 结构分类

**题目:** 以下数据结构中，______ 是非线性数据结构。

**选项:**
1. 树
